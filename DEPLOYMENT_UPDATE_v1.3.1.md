# Deployment update checklist — CoinDCX Strategy Terminal v1.3.1

## What changed
- `ADMIN_PASSWORD` is generated by the Render Blueprint for new/synced deployments. Startup remains available if the password is missing, and login fails closed rather than crashing the service.
- Manual order response handling now normalizes exchange status and treats a reported fill as `filled_unreconciled` until an exchange trade-history fill is recorded. Responses without an exchange order ID stay `unknown` and block automation until reconciled.
- Futures trade reconciliation imports account-wide trade-history rows for the configured 14-pair universe over a rolling lookback (default 3 days), including trades not linked to a bot-generated order. Duplicate fill and ledger IDs are idempotent across the account-wide/order-specific queries.
- Futures transaction ledger IDs include additional identity fields to reduce accidental collisions.
- Live unresolved orders remain an automation blocker regardless of age, rather than ceasing to block after two days.
- Paper trading, markets, strategy, live/manual/automatic live controls, positions, orders/fills, capital, ledger export, telemetry, analytics, backtest archive, journal, settings and health pages are included.

## Deploy to the existing Render project
1. Replace the connected Git repository contents with this package, including `render.yaml`, and push the commit.
2. In Render, sync/apply the Blueprint and deploy the new commit. A ZIP file by itself is not a deploy source.
3. Open the web service Environment. Confirm `ADMIN_PASSWORD` is set to a randomly generated value of at least 14 characters. If Render did not populate the generated value during sync, set it manually. Save it privately.
4. Ensure the web and worker share the same Render PostgreSQL `DATABASE_URL` and CoinDCX environment secret group, and are in the same region as the database.
5. Wait for the deployment to be healthy. Visit `/health` and confirm `ok: true` and `admin_auth_configured: true`.
6. Sign in using `ADMIN_USERNAME=admin` unless changed, and the private password from Render Environment.
7. Add CoinDCX credentials only through Render environment variables. Start with read-only permissions for account checks if possible.

## Live trading defaults
`LIVE_TRADING_ENABLED=false` and `AUTO_LIVE_TRADING_ENABLED=false` remain the defaults. Do not switch these on until market mapping, quote/quantity precision, account balances, status polling, trade fills, fee/funding transactions, position reconciliation and paper behavior have been checked. Auto-live additionally requires an authenticated administrator to type the explicit arming phrase. The worker disarms automation on startup/restart.

## Ledger scope
Spot account trade history and rolling futures account trade history are imported idempotently. Futures P&L, fees and funding are imported from transaction rows where the API exposes them. The futures fill-history sync uses a configurable rolling window, default three days, and a bounded page count; it is not a lifetime account-history archive. Any API errors or pagination ceilings should appear as reconciliation warnings and block auto-live. Verify balances and history against CoinDCX before relying on P&L.
